# AI地域商社

関西の生産者と飲食店をつなぎ、食材の仕入れ相談を支援するWebアプリです。

飲食店の「何を・どれだけ・いつまでに仕入れたいか」と、生産者の「今、何を・どれだけ出せるか」をもとに、複数の生産者を組み合わせた仕入れ案を提示します。

**[アプリを開く](https://ai-chiiki-general.vercel.app)**

AI BOOTCAMP 最終課題「デモデイで、証明せよ」の Issue E「関西の地産地消をAIで繋ぐ」に取り組むプロジェクトです。

## 解決したい課題

生産者ごとに出せる数量や受け渡し条件が異なると、飲食店は複数の相手に確認しながら仕入れを調整する必要があります。一方、生産者も、忙しい中で出品内容の入力や問い合わせへの対応を行います。

このアプリでは、両者の条件を整理し、「仕入れ案を探す → 生産者に相談する → 対応可能か返事をもらう」までを一つの流れにまとめています。入力や検索の負担を減らし、条件を確認しながら相談を進められることを目指しています。

## 主な機能

| 飲食店 | 生産者 |
| --- | --- |
| 希望する食材・数量・日程などの入力 | 食材・数量・価格・受け渡し条件の登録 |
| 複数の生産者を組み合わせた仕入れ案の確認 | 出品内容・販売可能数量の更新 |
| 生産者への仕入れ相談 | 相談内容の確認と対応可否の返答 |
| 相談状況・メッセージの確認 | 相談状況・メッセージの確認 |

会員登録、役割別の初期設定、マイページでの情報編集にも対応しています。生産者の連絡先は、相談への承認後に飲食店へ表示します。

## AIの役割

AIは自然文から食材や数量などの入力候補を整理する補助に使います。候補は利用者が確認・修正してから進めます。

数量の割り当てや条件の照合は通常のプログラムで処理し、AIの出力だけで取引を確定しない設計です。AIが利用できない場合は手入力で進められます。

## 課題解決の流れ

1. 飲食店が「トマトを10kg仕入れたい」と条件を入力する。
2. 生産者の出品情報をもとに、数量や受け渡し条件を確認できる仕入れ案を表示する。
3. 生産者の販売可能数量が変わった場合は、案を計算し直す。
4. 飲食店が相談を送り、生産者が対応できるか返答する。
5. 承認した生産者の連絡先を確認し、具体的な取引の調整へ進む。

相談への承認は、注文の確定や在庫の確保を意味しません。決済・配送手配はアプリ内では行いません。

## 技術構成

| 領域 | 使用技術 |
| --- | --- |
| フロントエンド | React / TypeScript / Vite / React Router |
| API | Vercel Functions |
| データベース | PostgreSQL（Neon） |
| データアクセス | Prisma |
| AIによる入力補助 | OpenAI API |
| テスト | Vitest / jsdom |
| ホスティング | Vercel |

データは「ブラウザ → API → データベース」の順に扱います。データベース接続情報やAIのAPIキーはサーバー側の環境変数で管理します。

## 工夫した点

- 飲食店と生産者の双方に、次の操作が分かる画面を用意する。
- 一つの生産者だけで数量が揃わない場合も、複数の出品を組み合わせて提案する。
- 在庫情報の変化を踏まえて、仕入れ案を再計算する。
- 画面の表示だけでなく、API側でもログイン状態や操作権限を確認する。
- 一般向け環境とデモ環境のデータベース・設定を分け、接続先の取り違えを検出する。

## ローカル開発

Node.js 22系と、開発専用のNeon PostgreSQL環境が必要です。本番用の接続情報は使用しないでください。

```sh
git clone https://github.com/kanaho123/ai-chiiki-mvp-redesign.git
cd ai-chiiki-mvp-redesign
npm ci
```

一般向けモードでは、プロジェクト直下の `.env.general.local` に開発用の設定を用意します。変数の概要は `.env.example` を参照してください。主にDB接続情報と `SESSION_SECRET` が必要で、AIを使用する場合は `OPENAI_API_KEY` と `OPENAI_MODEL` も設定します。一般向けモードでは `DEMO_NOW` を設定しません。

開発用DBは `server/db-safety.ts` と `server/app-mode.ts` の接続先チェックに適合する設定が必要です。デモ用モードは `.env.approval.local` を使用します。初期化・マイグレーションを行う前に、`server/local-env.ts` と各スクリプトの対象環境を確認してください。

```sh
# 一般向けモードで開発サーバーを起動
npm run dev:general

# テスト
npm test

# ビルド
npm run build
```

開発サーバーは通常 `http://localhost:5173` で起動します。`.env` ファイル、APIキー、DBの認証情報、ログイン用パスワードはリポジトリに含めません。
