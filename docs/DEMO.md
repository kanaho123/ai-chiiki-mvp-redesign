# 5分デモ手順（AI地域商社 MVP）

人物・農園・在庫・拠点・価格はすべて架空。デモの基準日時は `DEMO_NOW=2026-10-22T12:00:00+09:00`（木）。
**AI が使えなくても手入力で最後まで同じ結果になる**（実 OpenAI API は未検証。`docs/TODO.md` 参照）。

## 事前準備（デモの直前に1回）

1. デモデータを初期状態に戻す（デモ用 DB でだけ動く。元アプリの DB では止まる）
   ```
   npx tsx scripts/reset-demo.ts
   npx tsx scripts/check-demo-state.ts   # 「すべて初期状態どおりです」を確認
   ```
2. ログイン名：飲食店R `demo-r`／A農園 `demo-a`／B農園 `demo-b`（パスワードは `.env.local` の `DEMO_LOGIN_PASSWORD`）
3. 端末は1台でよい（ログアウト → 別のデモアカウントでログイン、で切り替える）。2台使う場合は飲食店用・生産者用に分ける

## 台本

| 時間 | 操作 | 期待する表示 |
| --- | --- | --- |
| 0:00〜0:40 | `demo-r` でログイン →「仕入れ案を作る」。手入力（または AI 読み取り）で条件を確定 | A農園10kg、商品代6,000円＋受渡費800円＝**総額6,800円**、「登録条件に適合」。1農家で揃うので分割しない |
| 0:40〜1:10 | ログアウト → `demo-a` でログイン → トマトの数量を 10 → **5** にして「数量を変更」 | 「10kg → 5kgに更新しました」 |
| 1:10〜2:00 | ログアウト → `demo-r` でログイン | 「供給情報が更新されています／この仕入れ案は現在の情報ではありません」 |
| 2:00〜3:00 | 「最新情報で再計算」 | A5kg＋B5kg、商品代5,750円＋受渡費800円＝**総額6,550円**。Bは「初回」 |
| 3:00〜3:30 | 「使わなかった供給と理由」を見る | D農園（300円/kg）は「別の受渡枠のため対象外」。安くても受渡条件が違えば混ぜない |
| 3:30〜4:20 | `demo-b` でトマトを 5 → **4** → `demo-r` で再計算 | 「この検索条件・最大3農家では9kg。1kg不足しています」、総額6,000円、状態は「条件を満たさない」 |
| 4:20〜4:50 | 「条件を変更」 | 候補は自動で適用されない。勝手に数量を変えず、架空のC在庫も足さない |

### 条件（手入力の場合）

品目トマト／10kg／受け取りたい日 2026-10-23／受渡枠 **G-P（受渡拠点P）**／産地 大阪府産／予算 金額を指定 8,000円／初回の農家「含める」／規格外「許可しない」／品種の混在「混ぜない」／規格の混在「混ぜない」／優先する取引先 A農園

### AI 読み取りを使う場合（OPENAI_API_KEY・OPENAI_MODEL 設定時のみ）

入力文：「10月23日金曜に大阪産トマト10kg、受渡費込み8,000円以内。A農園を優先、初回の農家もOK」
→ 確認画面で「要確認」の4項目（受渡枠・規格外・品種の混在・規格の混在）を上の条件どおりに選ぶ。
AI が失敗・未設定の場合は「手入力で指定する」を押す（入力文は残る）。

## デモ後

```
npx tsx scripts/reset-demo.ts
```

## 言える範囲（注意）

- 計算は登録条件の照合・集計・変動反映。AI は条件の候補を読み取るだけで、農家・数量・金額は決めない
- 提案は在庫予約ではない（「生産者への確認前・在庫未確保」）。注文・決済・連絡はできない
- 取引経験は店の申告情報で、品質・信用の保証ではない
