# 受け渡し場所を「場所だけ」で登録する（設計案・未実装）

ステータス：**一部を実装済み（2026-10-22、ブランチ `entry-flow-redesign`・未デプロイ）**。下の「おすすめ」案ではなく、受渡の回の仕組みを残す小さい形にした：

- 実装した：場所の登録は種類・名前・住所だけ（`producer_places` 表を追加。追加のみ）。出品のときに「今回渡せる日」と「午前／午後」を選び、その場所・日時の受渡の回を使う（なければ作る。同じ場所・日時なら複数の農家が同じ回にまとまる）。飲食店の受け取り日は任意（未定なら受け取れる回の中から探す）。細かい時刻はマッチング後のやり取りで決める。
- 実装していない：日時を持たない出品・相談（下の案）。必要になったら、この文書の案から進める。
- デプロイの順番：先にマイグレーション `20261022090000_producer_places` を適用してから、コードをデプロイする（一般向けの環境の `/api/supplies` がこの表を読むため）。

以下は元の設計案（2026-10-22 時点）。

## やりたいこと

- 生産者はマイページで「いつもの受け渡し場所」を **場所名と住所だけ** で登録する。曜日・時間は聞かない。
- 出品するときは、登録した場所から選ぶ。
- 曜日・時間などの細かい条件は、マッチング・相談の後に飲食店と生産者で決める。

## 今の仕組みと、なぜそのままではできないか

| もの | 今の作り |
|---|---|
| いつもの受け渡し場所 | `Place`（場所）と `SlotSeries`（毎週の曜日・時間）の組で登録する。生産者とは `SlotSeriesParticipant` でつながる。**場所だけを生産者に結びつける表がない** |
| 受け渡しの回 | `HandoverSlot`（場所＋開始・終了の日時＋確認締切・費用・上限kg）。`SlotSeries` から自動で作る（`slot-refill.ts`） |
| 出品 | `Supply.slotId` は **必須**。出品は必ず「ある日・ある時間の回」に結びつく。重複の判定も `[producerId, itemId, slotId]` |
| マッチング | `allocatePlan`（`src/lib/allocate.ts`）は **同じ回（slotId）の出品だけ** を束ねる。回の日付と希望日が一致すること、確認締切・上限kg・費用も回を見て判定する |
| 仕入れ相談 | `ApprovalRequest.pickupStartAt / pickupEndAt / pickupPlace` は **必須**。相談の時点で日時が決まっている前提 |

つまり、「受け取りは1か所・同じ日時」で複数の農家を束ねることが、DB とマッチングの両方の前提になっている。日時を持たない出品を入れるには、表の追加とマッチングの変更が必要になる。

## 案（おすすめ）：出品は「場所」と「出せる日」、時間は相談で決める

### データ（追加だけ。今の列・表は消さない）

1. `ProducerPlace`（新しい表）：生産者 × 場所。「いつもの受け渡し場所」の一覧。曜日・時間は持たない。
   - `producerId`, `placeId`, `createdAt`。`@@unique([producerId, placeId])`
   - 場所は今の `Place` をそのまま使う（生産者が新しく入れた場所は `ownerProducerId` 付き、運営の場所は null のまま）。
2. `Supply` に `placeId`（null 可）と `availableDate`（出せる日、null 可）を追加し、`slotId` を null 可にする。
   - 今の出品（slotId あり）はそのまま動く。新しい出品は `placeId`＋`availableDate` を持ち、slotId は null。
   - 重複の判定は、新しい出品では `[producerId, itemId, placeId, availableDate]`（部分一意インデックス）。
3. `ApprovalRequest.pickupStartAt / pickupEndAt` を null 可にし、`agreedPickupAt`（決まった受け渡し日時、null 可）を追加する。
   - 日時が未定の相談では、画面に「受け渡しの時間は、やり取りで決めます」と出す。決まったら、やり取りの画面から記録する。

### マッチング

- 束ねる単位を「同じ回」から「**同じ場所・同じ日**」に広げる（新しい出品だけ）。今の回ベースの出品は、今の判定のまま。
- 回が持っていた条件の扱い：
  - 確認締切：場所の受け渡し日の前日など、決まった規則にする（要相談）。
  - 上限kg・受け渡しの費用：場所ごとの既定値にするか、新しい出品では使わない（要相談）。
- 「受け取りは1か所」は変えない（別の場所の出品は束ねない）。

### 画面

- マイページの「いつもの受け渡し場所」：場所名・住所だけの入力（今の3つの質問のうち「いつ渡せますか？」をなくす）。
- 出品：受け渡しは「いつもの場所」から選ぶ＋「出せる日」を選ぶ（時間は聞かない）。
- 仕入れ案・相談：時間の代わりに「時間はやり取りで決めます」。成立後のやり取りの画面に「受け渡しの日時を決める」を置く。
